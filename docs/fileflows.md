# FileFlows on melon — Sonarr/Radarr transcoding middleman

Date: 2026-09-12
Goal: transcode downloads for Sonarr/Radarr before import. FileFlows sits between transmission and the *arrs: transmission saves into `complete/`, FileFlows processes the file and relocates it to `converted/`, and the *arrs import from `converted/` via Remote Path Mappings.

```
transmission → /mnt/media/downloads/complete
                 │  (FileFlows library watches this)
                 ▼
        FileFlows flow → /mnt/media/downloads/converted
                 │  (Sonarr/Radarr Remote Path Mapping points here)
                 ▼
       *arr import → library root (copy; CIFS has no hardlinks)
```

This is the official "middleman" integration (fileflows.com/docs/guides/sonarr-radarr). The arr→FileFlows webhook route is a paid feature and is not used; neither is FileFlows' built-in login (also licensed) — auth comes from a traefik basic-auth middleware instead.

## What Nix manages (do not do by hand)

- `virtualisation.oci-containers.containers.fileflows` in `generic/server/arr.nix` — image `revenz/fileflows:stable` (Docker Hub only), loopback port 19200 → container 5000, `PUID`/`PGID` = media (990/987).
- `/var/lib/fileflows/{Data,Logs,temp}` — tmpfiles-owned `media:media 0770`; `Data` holds the flow DB, `temp` is transcode scratch (local disk, never the share).
- `podman-fileflows.service` requires `mnt-media.mount` — if pumpkin is down at boot the container fails loudly instead of silently binding an empty local dir.
- Traefik: `https://fileflows.lc.brotherwolf.ca` (internal-only) with HTTP basic auth (`admin` / `fileflows-password.age`), generated by `traefik-fileflows-htpasswd.service` — same shape as the Loki route.
- transmission `download-dir = /mnt/media/downloads/complete` (incomplete stays `.../incomplete`, so FileFlows never sees partial files).
- `fileflows-converted-dir.service` — oneshot that creates `converted/` on the share (its `mkdir` triggers the CIFS automount; retries every 30s if pumpkin is down). Not a tmpfiles rule: tmpfiles runs before the automount fires, so the dir would land on the local root fs and get shadowed.

## One-time manual setup

1. Verify the dirs came up (after the first switch):
   ```bash
   findmnt -T /mnt/media -o SOURCE,FSTYPE -n   # must print cifs
   stat -c '%U:%G %a %n' /mnt/media/downloads/complete /mnt/media/downloads/converted
   ```
   (`converted/` is media:media 0770 from the mount's `uid=media gid=media dir_mode=0770` options; `complete/` appears once transmission restarts. If `fileflows-converted-dir` failed because pumpkin was down, `sudo systemctl start fileflows-converted-dir` once the share is back.)
2. Open `https://fileflows.lc.brotherwolf.ca` (LAN only) — basic auth: `admin` / the `fileflows-password.age` value.
3. **Library**: Libraries → Add → Path `/media/downloads/complete` — the **container** path, not the host path (classic mistake). Keep the file-system-events watcher on, but also enable a scan interval: inotify over CIFS only sees local changes, so the scan is the safety net.
4. **Flow**: Flows → Add, ending with the file under `/media/downloads/converted` — e.g. a stock video-transcode flow whose Library Output node has New Location `/media/downloads/converted`.

### Seeding caveat (decide before enabling)

transmission seeds to ratio 5.0 / idle 7 days (`generic/server/arr.nix`). A **move** out of `complete/` deletes the torrent's data and kills seeding immediately. Prefer the copy flavour:
- Library Output → On Completion = "Keep Original" (seeding-safe, 2× disk while seeding), or
- Move File node with "Delete Original" unchecked.

If you accept cutting ratio/idle limits short, move/delete is fine. This is a flow-level choice, not a Nix setting.

Note: neither transmission nor the *arrs remove the original once seeding ends. The ratio/idle limits only **stop** the torrent — the files stay in `complete/` until something deletes them, so the copy flavour accumulates disk over time. Options:
- Sonarr/Radarr → Settings → Download Clients → "Remove Completed Downloads": removes torrent + data right after import — i.e. seeding is cut short at *import* time, not after the limits. Only pick this if long seeding doesn't matter.
- Manually prune finished torrents in the transmission UI (Remove → also delete local data) — respects the ratio/idle limits but is a manual chore.
- `transmission-seeding-cleanup` (daily systemd timer in `generic/server/arr.nix`) is the automated option: it removes torrents whose `State:` is `Finished` (ratio/idle limits met) **and** whose `Location:` is under `complete/`, deleting data via transmission's own `--remove-and-delete`. Torrents from before the layout change (flat `downloads/`) are deliberately left alone. Sanity-check the state labels on melon before trusting it: `transmission-remote 192.168.15.1:9091 -n "$(cat /run/agenix/transmission.credentialsFile)" -t all -i | grep -E '^  (State|Location):'`. If it can't reach the RPC (whitelist/tunnel), the unit fails loudly and the timer retries the next day.

## Sonarr and Radarr (both apps)

Settings → Download Clients → Remote Path Mappings → Add:

| Field | Value |
|---|---|
| Remote Path | `/mnt/media/downloads/complete` |
| Local Path | `/mnt/media/downloads/converted` |

Use **host** paths — transmission and the *arrs are host services; the `/media/...` strings in the FileFlows guide are container paths. Without the mapping the *arrs look in `complete/`, find nothing, and Queue items sit at "importing" forever.

The mapping only rewrites the path prefix, so the FileFlows flow must keep the output **filename** identical to the source — a container change (mkv → mp4) makes the mapped lookup miss and the import stall. If you do want to change containers, use the community "Sonarr/Radarr - Trigger Manual Import" flow script (drives the *arr API with the real output path) instead of relying on the mapping. Copy vs move is irrelevant to the mapping itself: with the copy flavour the *arr imports the converted copy while the original keeps seeding, so disk peaks at ~2× until `transmission-seeding-cleanup` deletes the original after seeding ends.

## Updating the image

`pull = "missing"` means `nixos-rebuild switch` does **not** re-pull the moving `stable` tag:

```bash
sudo podman pull docker.io/revenz/fileflows:stable
sudo systemctl restart podman-fileflows
```

Pin a `YY.MM` tag or digest in `arr.nix` if you want reproducible rebuilds.

## Operations / troubleshooting

- `systemctl status podman-fileflows` / `journalctl -u podman-fileflows` (log-driver journald); UI logs also in `/var/lib/fileflows/Logs`.
- `curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:19200/` — 200/302 when healthy.
- `sudo podman exec fileflows id` — expect `uid=990 gid=987`; if it says root, the image ignored PUID/PGID (cosmetic on the share — the CIFS mount presents everything as media — but files under `/var/lib/fileflows` would be root-owned).
- Traefik route: `https://traefik.lc.brotherwolf.ca` → Routers → `fileflows@file`; 401 on the route means the htpasswd oneshot didn't run (check the secret exists: `agenix -e secrets/fileflows-password.age`).
- Container is recreated on every switch — anything it writes outside the four mounted volumes is lost (e.g. runtime-downloaded ffmpeg; if a tools dir reappears in `/app` after rebuilds, mount it).
- pumpkin down at boot → `podman-fileflows` fails (mount guard) and `fileflows-converted-dir` keeps retrying every 30s. After the NAS is back: `sudo systemctl start fileflows-converted-dir podman-fileflows`. Stop the container before `systemctl stop mnt-media.mount` (its bind mount holds the share busy).
- `/var/lib/fileflows/Data` (flows + DB) is **not backed up** — borgmatic runs on onion only. Export flows or accept the loss.

## Rollback

Revert the Nix changes, restart transmission (download-dir back to `/mnt/media/downloads`), `sudo podman rm -f fileflows`, optionally remove `/var/lib/fileflows`. Files already in `converted/` stay where they are.
